# SPU Smart Classroom · CiRA CORE Attendance

โครงงานต้นแบบเช็คชื่อด้วยใบหน้า และสรุปพฤติกรรมในห้องเรียน (ตั้งใจเรียน / หลับ) จากผลตรวจจับของ CiRA CORE สำหรับ **มหาวิทยาลัยศรีปทุม (SPU)** เป็นผลงานนักศึกษาอิสระ ไม่ใช่ระบบทางการของมหาวิทยาลัย

## ความสามารถ

- เข้าสู่ระบบแยก 2 บทบาท: **ผู้ดูแล** (เตรียมข้อมูลทั้งหมด) และ **อาจารย์** (เลือกห้อง → เลือกเซ็คของตัวเอง → เริ่มคาบ)
- ผู้ดูแลสร้างห้องและเซ็ค นำเข้ารายชื่อนักศึกษาจาก CSV ทีละเซ็ค แล้วถ่ายภาพใบหน้าให้คนที่ยังไม่มี
- ลงทะเบียน 3–8 ภาพต่อคน พร้อมการยินยอมและลบข้อมูล
- ตรวจใบหน้าด้วย Haar cascade และรู้จำด้วย OpenCV LBPH เช็คชื่อเฉพาะคนที่อยู่ในรายชื่อเซ็ค คนละหนึ่งครั้งต่อคาบ
- เปิดคาบได้ห้องละ 1 คาบพร้อมกัน CiRA ส่งรหัสห้องมาเพื่อแยกว่าเฟรมนี้เป็นของห้องไหน
- รับผล DeepDetect จาก CiRA CORE ผ่าน `POST /api/cira/frame` แล้วแสดงกรอบสีตามพฤติกรรมบนภาพล่าสุด
- สรุปทั้งห้อง: % ตั้งใจเรียน, จำนวนคนหลับ, จำนวนคนในภาพ (เฉลี่ย 10 วินาทีล่าสุด)
- สรุปรายคน เมื่อ CiRA แนบภาพเฟรมเดียวกันมาและระบบจำหน้าได้ในกรอบนั้น
- ตรวจการใช้โทรศัพท์เป็นตัวเลือก **ปิดไว้เป็นค่าเริ่มต้น** (กล้องหน้าห้องมักโดนคนข้างหน้าบัง)
- ตั้งชื่อคลาสของโมเดล รูปแบบกรอบ และสเกล confidence ได้จากหน้าตั้งค่า โดยไม่ต้องแก้โค้ด
- รายงานรายนาทีและรายบุคคล ส่งออก CSV UTF-8 สำหรับ Excel
- ตัวส่งข้อมูลจำลองสำหรับสาธิตก่อนมีโมเดลจริง แยกเป็น "คาบจำลอง" และติดป้าย **ข้อมูลจำลอง** ทุกจุด
- รูปใบหน้าที่ครอป ฐานข้อมูล และ API key เก็บใน `data/` ซึ่งถูก gitignore ภาพจาก CiRA เก็บในหน่วยความจำเฉพาะเฟรมล่าสุด ไม่เขียนลงดิสก์

## เริ่มใช้งาน (Python 3.9–3.12)

```bash
git clone https://github.com/Porlager/spu-cira-attendance.git
cd spu-cira-attendance
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Windows ใช้ `py -m venv .venv` และ `.venv\Scripts\activate` แทนสองคำสั่งสร้าง/เปิด venv

เปิด **http://127.0.0.1:5050** ใน Chrome หรือ Edge ครั้งแรกระบบจะให้สร้างบัญชีผู้ดูแล

**ผู้ดูแล (ทำครั้งเดียวต่อเทอม)**
1. **ผู้ใช้งาน**: สร้างบัญชีอาจารย์ (ชื่อผู้ใช้ + รหัสผ่านเริ่มต้น)
2. **ห้องและเซ็ค**: เพิ่มห้อง เช่น `11-501` แล้วเพิ่มเซ็ค เช่น `CPE447 · 01` เลือกห้องและอาจารย์ผู้สอน
3. ในหน้าเซ็ค นำเข้ารายชื่อจาก CSV (คอลัมน์ 1 = รหัส, คอลัมน์ 2 = ชื่อ ดู [ไฟล์ตัวอย่าง](static/roster-template.csv)) ระบบแสดงตัวอย่างก่อนยืนยัน
4. **ลงทะเบียนใบหน้า**: ค้นหานักศึกษาที่ยังไม่มีใบหน้า ถ่าย 3–8 ภาพ ติ๊กยินยอม แล้วบันทึก

**อาจารย์ (ทุกคาบ)**
1. เข้าสู่ระบบ → เลือกห้อง → เลือกเซ็คที่สอน → กด "เริ่มคาบ"
2. ให้ CiRA CORE ส่งผลเข้ามาตาม [คู่มือต่อ CiRA CORE (PDF)](docs/CIRA_GUIDE.pdf) หรือ [ฉบับย่อ](docs/CIRA_SETUP.md) หรือสลับเป็น "กล้องเครื่องนี้" เพื่อเช็คชื่อจากเว็บแคม (ไม่ตรวจพฤติกรรม)
3. ตรวจทานผลกับคนจริง ปิดคาบ แล้วดูสรุปและดาวน์โหลด CSV ในหน้า **รายงาน**

## ทดลองโดยยังไม่มีโมเดล

เปิด `python app.py` ไว้ แล้วรันในอีกหน้าต่าง:

```bash
python integrations/simulate_cira.py --seconds 120 --with-identities
python integrations/simulate_cira.py --section 1 --with-identities   # จำลองเซ็ค id 1 ในห้องของเซ็คนั้น
```

- ตัวจำลองเปิด "คาบจำลอง" ให้เอง และปิดให้เมื่อจบ (`--keep-open` เพื่อเปิดค้างไว้)
- ถ้ามีคาบจริงเปิดอยู่ ตัวจำลองจะไม่ส่งข้อมูล ระบบไม่ยอมให้ข้อมูลจำลองปนกับคาบจริง
- `--with-identities` ผูกรหัสนักศึกษาที่มีภาพใบหน้าแล้วกับที่นั่งจำลอง (คนที่หลับหรือยังไม่มีภาพใบหน้าจะไม่ถูกระบุตัว เหมือนกล้องจริง)
- **ตัวเลขจากตัวจำลองเป็นข้อมูลสุ่ม ห้ามนำไปอ้างเป็นผลทดลอง**

## พฤติกรรมคำนวณอย่างไร

- **ตั้งใจเรียน (%)** = ตั้งใจ ÷ (ตั้งใจ + ไม่ตั้งใจ + หลับ + ใช้โทรศัพท์ถ้าเปิดไว้) กรอบ "คน" ที่ไม่ระบุพฤติกรรมไม่นับ
- **หลับ** นับทั้งห้อง รวมคนที่ระบบระบุตัวไม่ได้
- **รายคน**: ใบหน้าที่จำได้จะผูกกับกรอบพฤติกรรมที่มีจุดกึ่งกลางใบหน้าอยู่ข้างใน ถ้าซ้อนหลายกรอบเลือกกรอบเล็กสุด ถ้ากำกวม (สองคนในกรอบเดียว) จะไม่ผูก
- สถานะรายคนบนหน้าห้องเรียนเปลี่ยนเมื่อเห็นพฤติกรรมเดิมติดกัน 3 เฟรม (ตั้งได้) กันการกระพริบ
- สัดส่วนรายคนในรายงานนับเป็น **เฟรมที่ผูกได้** ไม่ใช่นาทีจริง

## โครงสร้าง

```text
app.py                     API + SQLite + login, rooms, sections, sessions, live state
roster.py                  อ่าน CSV รายชื่อ (UTF-8 / ภาษาไทยของ Excel) และตรวจความถูกต้อง
behavior.py                กติกาพฤติกรรม: แปลงคลาส, normalize กรอบ, จับคู่ใบหน้า, กันกระพริบ
vision.py                  Haar face detector + LBPH recognizer
templates/ static/         หน้าเว็บภาษาไทย (vanilla JS, ไม่ใช้ CDN)
integrations/cira_bridge.py    ส่งผล CiRA เข้า web app
integrations/cira_python_plus.py  โค้ดสำหรับ Python+ node ใน CiRA (INPUT + OUTPUT)
integrations/simulate_cira.py  ข้อมูลจำลองสำหรับสาธิต
tests/                     isolated tests, no real student data
docs/                      CiRA guide (PDF), web preview (PDF), presentation outline
data/                      LOCAL ONLY, auto-created and ignored
```

## ทดสอบ

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

CI ทดสอบ Python 3.11 บน GitHub Actions โดยใช้ฐานข้อมูลชั่วคราวและข้อมูลสังเคราะห์ เป็นการทดสอบ workflow ไม่ใช่หลักฐานความแม่นยำในชีวิตจริง

## สถานะ CiRA CORE

มี API, bridge และตัวจำลองที่ทดสอบด้วยข้อมูลสังเคราะห์ **ยังไม่ได้ตรวจรับบน CiRA CORE หรือกล้องห้องเรียนจริง และยังไม่มีโมเดลตรวจพฤติกรรม** ชื่อคลาสเริ่มต้น (`awake`, `distracted`, `sleep`, `phone`, `person`) เป็นค่าตัวอย่าง ต้องแก้ให้ตรงกับโมเดลที่ฝึกจริงในหน้าตั้งค่า รูปแบบกรอบตั้งตามเอกสาร CiRA (x,y จุดกึ่งกลาง, พิกเซล, confidence 0–1) ไม่มี native CiRA flow รวมอยู่ใน repo มีเพียงโค้ด Python+ node ที่ทดสอบกับตัวจำลอง

## ข้อจำกัดที่ต้องอธิบายตอนส่ง

- LBPH เป็น baseline สำหรับการเรียนรู้ ไม่ใช่ face embedding สมัยใหม่; แสง มุมหน้า และกล้องมีผลมาก ปรับ `LBPH_THRESHOLD` ได้ (ค่าเริ่มต้น 55; ระยะยิ่งต่ำยิ่งคล้าย)
- ไม่มี liveness/anti-spoofing: รูปภาพหรือจออาจหลอกระบบได้ ต้องมีผู้สอนตรวจทาน
- ผลพฤติกรรมเป็นการประเมินของโมเดล ผิดพลาดได้ (เช่น ก้มเขียนหนังสืออาจดูเหมือนหลับ) **ไม่ควรใช้ตัดคะแนนหรือลงโทษ** ใช้ประกอบการสังเกตของผู้สอนเท่านั้น และควรแจ้งนักศึกษาก่อนใช้
- คนที่ก้มหน้าหลับมักจำหน้าไม่ได้ จึงอยู่ในยอดรวมของห้องแต่ไม่มีชื่อในรายบุคคล
- จำนวนคนเป็นค่าเฉลี่ยช่วงสั้นจากภาพล่าสุด ไม่ใช่ยอดสะสมหรือจำนวนนักศึกษาที่ไม่ซ้ำ
- รายงานและ CSV ใช้รายชื่อเซ็คขณะเปิดดู ไม่ใช่ snapshot ตอนเรียน; การลบนักศึกษาลบประวัติบุคคลนั้นทุกคาบด้วย
- มีบัญชีผู้ใช้ (รหัสผ่านเก็บแบบ hash, session cookie + CSRF) แต่ยังไม่มี HTTPS จึงเปิดเฉพาะ localhost อาจารย์ใช้เครื่องเดียวกับ CiRA ไม่ควร deploy public
- ไม่ได้อ้างผล accuracy, FPS หรือผลการทดลอง จนกว่าจะทดสอบจริงตาม [แผนทดลอง](docs/PROJECT.md)

## ข้อมูลส่วนตัวและ public repo

Public เฉพาะ source code ไม่ใส่ข้อมูลนักศึกษาจริง รูปใบหน้า CSV ห้องเรียน payload จากห้องจริง หรือ key ลง git อย่า force-add โฟลเดอร์ `data/` และ `exports/` ผู้ที่เข้าใช้บัญชี OS เดียวกันสามารถเข้าถึงข้อมูลในเครื่องได้ ฐานข้อมูลยังไม่ได้เข้ารหัส สำรองหรือย้ายข้อมูลต้องได้รับความยินยอมและจัดการตามข้อกำหนดของสถาบัน

ปิดเซิร์ฟเวอร์ด้วย Ctrl+C เปลี่ยน port ด้วย `PORT=5051 python app.py` สามารถตั้ง `SPU_DATA_DIR` ไปยังโฟลเดอร์ส่วนตัวนอก repo ได้
