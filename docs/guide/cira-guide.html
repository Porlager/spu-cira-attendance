สถานะ
API และโค้ด Python+ ทดสอบแล้วด้วยข้อมูลสังเคราะห์และตัวจำลอง ยังไม่ได้ตรวจรับบน CiRA CORE จริง

สรุปสั้นสำหรับคนรีบ

  1. ติดตั้งเว็บบนเครื่องเดียวกับ CiRA CORE (รุ่น desktop) แล้วรัน python app.py เปิด http://127.0.0.1:5050
  2. ผู้ดูแล สร้างห้อง (เช่น 11-501) เซ็ค รายชื่อ และภาพใบหน้า แล้ว อาจารย์ เข้าสู่ระบบ → เลือกห้อง → เลือกเซ็ค → เริ่มคาบ (ไม่เปิดคาบ = ข้อมูลถูกปฏิเสธ)
  3. ดู Debug ของ DeepDetect จดชื่อคลาสที่โมเดลส่งออกมา
  4. หน้า "ตั้งค่า CiRA" จับคู่ชื่อคลาสกับพฤติกรรม (รูปแบบกรอบตั้งตามเอกสาร CiRA ไว้แล้ว)
  5. วาง Python+ node ต่อจาก DeepDetect ใส่โค้ดจาก integrations/cira_python_plus.py แก้ REPO และ ROOM (รหัสห้องของกล้องตัวนี้)
  6. ตรวจผล หน้า "ห้องเรียน" ต้องมีกรอบทับคนพอดีและแถบบนเป็นจุดเขียว ส่วน Debug ใน CiRA ต้องเห็น payload.spu.status = "ok"

INPUT กับ OUTPUT คืออะไรในงานนี้

ทิศทางข้อมูลช่องทาง
INPUT CiRA → เว็บผล DeepDetect ต่อเฟรม (ชื่อคลาส, confidence, กรอบ) + ภาพเฟรมเดียวกัน (ไม่บังคับ)Python+ → POST /api/cira/frame
INPUT CiRA → เว็บผลของ function อื่น เช่น DeepClassif ไว้ดูโครงสร้าง (ไม่นำไปคำนวณ)POST /api/cira/output
OUTPUT เว็บ → flowผลสรุปเฟรมล่าสุดใส่กลับใน payload: จำนวนคน, % ตั้งใจ, หลับ, ใครถูกจำได้และทำอะไรอยู่payload["spu"] ให้ node ถัดไปใช้
OUTPUT เว็บ → CiRAสรุปทั้งห้องช่วง 10 วินาที + รายชื่อพร้อมสถานะ (ใช้ทำแจ้งเตือนได้)GET /api/live
OUTPUT เว็บ → คนหน้าห้องเรียนสด, รายงานรายนาที/รายคน, ไฟล์ CSVหน้าเว็บ / GET /api/sessions/<id>/export

ต้องรันบนเครื่องเดียวกัน เว็บรับเฉพาะ 127.0.0.1 / localhost ถ้า CiRA อยู่อีกเครื่อง ให้ย้ายเว็บไปไว้เครื่อง CiRA อย่าเปลี่ยนเป็น 0.0.0.0 เพราะยังไม่มีระบบล็อกอินและ HTTPS

ต้องใช้ CiRA CORE รุ่น desktop รุ่น browser (ciracore.cira-ai.com) ไม่มี Python+ และ REST node

1. ติดตั้งและเตรียมเว็บ

ต้องใช้ Python 3.9–3.12 บนเครื่องที่รัน CiRA CORE (เว็บใช้ Python ของตัวเอง แยกจาก Python ที่ CiRA ใช้)

git clone https://github.com/Porlager/spu-cira-attendance.git
cd spu-cira-attendance
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py                      # เปิด http://127.0.0.1:5050
  • ครั้งแรกระบบสร้างโฟลเดอร์ data/ พร้อม data/api-token.txt (API key) และฐานข้อมูล data/attendance.sqlite3
  • เปลี่ยน port ด้วย PORT=5051 python app.py เก็บข้อมูลที่อื่นด้วย SPU_DATA_DIR=/path python app.py
  • path เต็มของไฟล์ API key ดูได้ในหน้า "ตั้งค่า CiRA" หัวข้อ "การเชื่อมต่อ"

เตรียมก่อนส่งข้อมูล

  1. เปิดเว็บครั้งแรกจะให้สร้าง บัญชีผู้ดูแล แล้วสร้างบัญชีอาจารย์ในหน้า "ผู้ใช้งาน"
  2. หน้า ห้องและเซ็ค: เพิ่มห้อง (รหัสห้องนี้คือค่า ROOM ที่ CiRA ส่งมา) เพิ่มเซ็ค เลือกห้องและอาจารย์ แล้วนำเข้ารายชื่อจาก CSV
  3. หน้า ลงทะเบียนใบหน้า: ค้นหานักศึกษาที่ยังไม่มีใบหน้า ถ่าย 3–8 ภาพ ติ๊กยินยอม แล้วบันทึก (เฉพาะคนที่ยินยอม)
  4. อาจารย์ เข้าสู่ระบบ → เลือกห้อง → เลือกเซ็ค → "เริ่มคาบ" เปิดได้ห้องละ 1 คาบ ปิดด้วยปุ่ม "ปิดคาบ" ในหน้าห้องเรียน

ทดลองก่อนมีโมเดล (ไม่บังคับ)

ใช้ตัวจำลองดูว่าหน้าเว็บทำงานอย่างไร ระบบเปิด "คาบจำลอง" แยกให้และติดป้าย ข้อมูลจำลอง ทุกจุด ตัวจำลองส่งกรอบรูปแบบเดียวกับ DeepDetect จริง

python integrations/simulate_cira.py --seconds 120 --with-identities

ตัวจำลองไม่ทำงานถ้ามีคาบจริงเปิดอยู่ และเว็บไม่รับข้อมูลจำลองเข้าคาบจริง ตัวเลขจากตัวจำลองเป็นค่าสุ่ม ห้ามใช้เป็นผลทดลอง

2. อ่าน Debug ของ DeepDetect

ต่อ Debug node หลัง DeepDetect แล้วดูโครงสร้างจริงของรุ่นที่ติดตั้ง ตามเอกสาร CiRA CORE 2025 (JavaScript Update หน้า 27–28) ผล DeepDetect หน้าตาประมาณนี้:

{
  "DeepDetect": {
    "count": 2,
    "counts": {"awake": 1, "sleep": 1},
    "im_w": 1280, "im_h": 720,
    "objects": [
      {"id": 0, "name": "awake", "confidence": 0.91, "x": 290, "y": 390, "w": 180, "h": 260},
      {"id": 1, "name": "sleep", "confidence": 0.84, "x": 650, "y": 390, "w": 180, "h": 260}
    ]
  }
}

ตัวอย่างนี้เขียนขึ้นตามรูปแบบในเอกสาร ตัวเลขไม่ใช่ผลจากโมเดลจริง

fieldตามเอกสาร CiRAสิ่งที่ต้องเช็คบนเครื่องจริง
nameชื่อคลาสที่ตั้งตอนเทรนโมเดลจดทุกชื่อ ไปจับคู่ในหน้าตั้งค่า
x, yจุดกึ่งกลางกรอบ หน่วยพิกเซลกรอบบนเว็บต้องทับคนพอดี
w, hกว้าง/สูงของกรอบ พิกเซล—
confidence0–1 (บนจอแสดงเป็น % แต่ค่าใน payload เป็น 0–1)ถ้าเห็นค่าเกิน 1 ให้ตั้งสเกล 0–100
im_w, im_hขนาดภาพที่ใช้ตรวจ เว็บใช้แปลงพิกัดให้อัตโนมัติถ้าไม่มี ต้องแนบภาพหรือส่ง width/height
key DeepDetectบาง build ใช้ชื่ออื่น เช่น DeepDetectCPUถ้ามี detector เดียว ระบบหาเอง ถ้ามีหลายตัวต้องระบุ

3. ตั้งค่าให้ตรงกับโมเดล

เปิดหน้า ตั้งค่า CiRA แก้แล้วกด "บันทึกการตั้งค่า" มีผลกับเฟรมถัดไปทันที ไม่ต้องรีสตาร์ท

การจับคู่คลาส

ใส่ชื่อคลาสให้ตรงกับ Debug (ตัวพิมพ์เล็ก/ใหญ่ไม่มีผล) แล้วเลือกว่าหมายถึงอะไร ชื่อที่ใส่ไว้ตอนนี้ (awake, distracted, sleep, phone, person) เป็นตัวอย่าง:

เลือกความหมาย
ตั้งใจเรียนกรอบพฤติกรรมของคนหนึ่งคน นับเป็นตัวตั้งของ % ตั้งใจเรียน
ไม่ตั้งใจเช่น หันคุย มองที่อื่น
หลับนับในยอดหลับของทั้งห้อง และผูกกับชื่อถ้าจำหน้าได้
ใช้โทรศัพท์ (ทดลอง)นับเฉพาะเมื่อเปิดสวิตช์ "ตรวจการใช้โทรศัพท์" ถ้าปิด กรอบนี้นับเป็นคนในภาพเท่านั้น
คน (นับจำนวนอย่างเดียว)กรอบ person ทั่วไป ใช้นับจำนวนคน ไม่นับใน % ตั้งใจ
ไม่นับข้ามคลาสนี้ เช่น chair, book

คลาสที่ CiRA ส่งมาแต่ยังไม่ได้จับคู่ จะขึ้นเป็นปุ่ม "+ ชื่อคลาส" ใต้ตาราง กดเพื่อเพิ่มได้ทันที ระหว่างนั้นระบบข้ามคลาสนั้นไปก่อน

สูตร: ตั้งใจเรียน (%) = ตั้งใจ ÷ (ตั้งใจ + ไม่ตั้งใจ + หลับ + ใช้โทรศัพท์ถ้าเปิด) · จำนวนคน = ค่ามากกว่าระหว่างจำนวนกรอบ "คน" กับจำนวนกรอบพฤติกรรม จึงใช้โมเดล person กับโมเดลพฤติกรรมพร้อมกันได้โดยไม่นับซ้ำ

รูปแบบข้อมูลและพฤติกรรม

ช่องค่าเริ่มต้นหมายเหตุ
ตำแหน่ง x, y ของกรอบจุดกึ่งกลางตรงกับ DeepDetect ถ้ากรอบเลื่อนไปซ้ายบนครึ่งกรอบ แปลว่าข้อมูลเป็นมุม ให้เลือก "มุมซ้ายบน"
หน่วยพิกัดพิกเซลใช้ im_w/im_h ใน payload หรือภาพที่แนบมาแปลงให้
สเกล confidence0–1หรือ 0–100 ระบบหารให้เอง ห้ามหารซ้ำใน Python+
confidence ขั้นต่ำ0.5ต่ำกว่านี้ไม่นับ
ยืนยันสถานะรายคน (เฟรม)3ต้องเห็นพฤติกรรมเดิมติดกัน N เฟรมก่อนเปลี่ยนสถานะ กันกระพริบ
ตรวจการใช้โทรศัพท์ปิดกล้องหน้าห้องมักโดนบัง ทดลองแล้วค่อยตัดสินใจ

INPUT OUTPUT 4. Python+ node (แนะนำ)

Python+ node ของ CiRA ใช้ฟังก์ชัน handle_request(req) ที่อ่านข้อมูลด้วย getReqData(req) และส่งต่อด้วย makeRespData(payload, img) (Intro 2025 หน้า 14) ไฟล์ integrations/cira_python_plus.py ใน repo เขียนตามแบบนั้นแล้ว:

import sys

REPO = "/absolute/path/spu-cira-attendance"   # <-- แก้บรรทัดนี้ให้ตรงกับเครื่อง
BASE_URL = "http://127.0.0.1:5050"
ROOM = "11-501"          # รหัสห้องของกล้องตัวนี้ (เว้นว่างได้ถ้าเปิดคาบทีละห้อง)
SEND_IMAGE = True        # False = ส่งเฉพาะกรอบ (เช็คชื่อรายคนไม่ได้)
TIMEOUT = 2              # วินาที กัน flow ค้างถ้าเว็บไม่ตอบ

sys.path.append(REPO + "/integrations")
from cira_bridge import error_message, flow_output, send_detections

TOKEN_FILE = REPO + "/data/api-token.txt"
_last = {"status": "waiting"}

def handle_request(req):
    global _last
    payload, img = getReqData(req)
    frame = img if SEND_IMAGE and getattr(img, "size", 0) else None
    try:
        result = send_detections(payload, TOKEN_FILE, frame_bgr=frame,      # INPUT
                                 base_url=BASE_URL, timeout=TIMEOUT, room=ROOM or None)
        if result is not None:
            _last = dict(flow_output(result), status="ok")
    except Exception as error:      # เว็บปิด/ยังไม่เปิดคาบ: flow ต้องเดินต่อ
        _last = {"status": "error", "error": error_message(error)}
    payload["spu"] = _last                                                # OUTPUT
    return makeRespData(payload, img)

สิ่งที่โค้ดนี้ทำ

  • INPUT: ส่ง payload ของ DeepDetect ทั้งก้อน + ภาพ img เข้าเว็บ ระบบหา objects, im_w, im_h เอง ย่อภาพเหลือกว้างไม่เกิน 1280 px
  • ส่งจริงไม่เกิน 1 ครั้งต่อวินาที เฟรมที่เว้นไว้จะได้ผลล่าสุดซ้ำ จึงไม่ถ่วง flow ทุกเฟรม
  • OUTPUT: ใส่ผลกลับใน payload["spu"] ให้ node ถัดไปใช้ (รายละเอียดหัวข้อ 6.1)
  • ไม่ทำให้ flow หยุด ถ้าเว็บปิดหรือส่งไม่ผ่าน จะได้ payload["spu"]["status"] = "error" พร้อมเหตุผล

ต้องเช็คบนเครื่องจริงก่อน (ยังไม่ได้ทดสอบกับ CiRA ตัวจริง):

  • ใส่ print(type(img), getattr(img, "shape", None)) ชั่วคราว ภาพควรเป็น numpy BGR เช่น (720, 1280, 3) ถ้าติ๊ก "Not use image" ไว้ img อาจว่าง โค้ดจะส่งเฉพาะกรอบ
  • Python ที่ Python+ ใช้ (เลือกได้ด้วยปุ่ม Browse) ต้องมี opencv และ numpy ซึ่งปกติมีอยู่แล้ว bridge ใช้แค่ standard library นอกนั้น รองรับ Python 3.8 ขึ้นไป
  • ถ้ามี detector หลายตัวใน payload ให้ส่ง function="ชื่อ key" เพิ่มใน send_detections(...)

ส่งผลของ function อื่นมาดู

เช่น DeepClassif ส่งมาดูโครงสร้างในหน้าตั้งค่าได้ (ไม่นำไปคำนวณ เก็บในหน่วยความจำ ขนาดไม่เกิน 64 KB):

from cira_bridge import send_output
send_output("DeepClassif", payload.get("DeepClassif"), TOKEN_FILE, timeout=2)

พารามิเตอร์ของ send_detections

ชื่อค่าเริ่มต้นใช้ทำอะไร

width, heightจาก im_w/im_hใส่เองเมื่อ payload ไม่มี im_w/im_h และไม่แนบภาพ

กติกาภาพที่แนบ

  • ต้องเป็น เฟรมเดียวกับผลตรวจ ย่อได้ แต่ ห้าม crop ไม่อย่างนั้นกรอบจะไม่ตรงหน้า
  • ภาพเก็บในหน่วยความจำเฉพาะเฟรมล่าสุด ไม่เขียนลงดิสก์ ปิดคาบแล้วหายทันที
  • ระบบผูกใบหน้ากับกรอบพฤติกรรมที่ จุดกึ่งกลางใบหน้าอยู่ในกรอบ ถ้าซ้อนหลายกรอบเลือกกรอบเล็กสุด ถ้าสองคนอยู่ในกรอบเดียว ระบบจะไม่ผูกกับใคร
  • คนที่ฟุบหลับมักจำหน้าไม่ได้ จะอยู่ในยอดหลับของห้องแต่ไม่มีชื่อ เป็นพฤติกรรมที่ตั้งใจไว้

INPUT 5. สัญญา HTTP (กรณีไม่ใช้ Python+)

ใช้เมื่อส่งจากเครื่องมืออื่น ต้องมี header X-API-Key ที่อ่านจากไฟล์ทุกครั้ง ห้ามพิมพ์คีย์ลงใน flow รับทั้ง POST และ PUT และรับได้สองรูปแบบ:

แบบที่ 1: payload ของ CiRA ทั้งก้อน

POST http://127.0.0.1:5050/api/cira/frame
Content-Type: application/json
X-API-Key: <อ่านจาก data/api-token.txt>

{"room": "11-501",
 "DeepDetect": {"im_w": 1280, "im_h": 720,
                "objects": [{"name": "sleep", "confidence": 0.82, "x": 140, "y": 165, "w": 80, "h": 90}]},
 "image": "<base64 JPEG/PNG ไม่บังคับ>"}

ห่อเป็น {"payload": {...}} ก็ได้ ถ้ามี detector หลาย key ให้เพิ่ม "function": "ชื่อ key"

แบบที่ 2: รายการกรอบที่จัดเอง

{"function": "DeepDetect", "width": 1280, "height": 720,
 "detections": [{"name": "sleep", "confidence": 0.82, "x": 140, "y": 165, "w": 80, "h": 90}]}
fieldชนิดกติกา
objects / detectionslistไม่เกิน 300 รายการ ส่ง [] ได้เมื่อไม่พบใคร
└ namestring1–64 ตัวอักษร
└ confidencenumber0 ถึงสเกลที่ตั้งไว้ (1 หรือ 100)
└ x, y, w, hnumberw, h > 0 กรอบที่ล้นภาพจะถูกตัดให้อยู่ในภาพ
width, heightinteger1–10000 ใช้ im_w/im_h แทนได้ ต้องมีอย่างใดอย่างหนึ่งเมื่อหน่วยเป็นพิกเซล
imagestringbase64 หรือ data URL ไม่เกิน 3 MB ด้านยาวไม่เกิน 4096 px
roomstringรหัสห้อง เช่น 11-501 ต้องใส่เมื่อมีหลายห้องเปิดคาบพร้อมกัน
session_idintegerไม่บังคับ ถ้าใส่ต้องเป็นคาบที่เปิดอยู่ (ใช้แทน room ได้)

REST node ของ CiRA (RestPutJson): มีใน palette รุ่น desktop แต่ไม่พบเอกสารวิธีตั้ง URL และ header ถ้าใส่ header X-API-Key ไม่ได้ จะใช้ส่งเข้าเว็บนี้ไม่ได้ ให้ใช้ Python+ แทน · JavaScript node ไม่มีเอกสารเรื่องการเรียก HTTP จึงไม่แนะนำ

ทางเดิมที่ยังใช้ได้: POST /api/cira/observations (จำนวนคนอย่างเดียว) และ POST /api/recognize (เช็คชื่อจากภาพอย่างเดียว) ทั้งสองทางไม่สร้างข้อมูลพฤติกรรม

OUTPUT 6. อ่านผลกลับจากเว็บ

6.1 ใน flow ของ CiRA: payload["spu"]

หลัง Python+ node ทุกเฟรมจะมี payload.spu ต่อ Debug เพื่อดู หรือใช้ใน node ถัดไป:

"spu": {
  "status": "ok", "seq": 41,
  "people": 24, "attentive_pct": 79.2,
  "sleeping": 3, "inattentive": 2, "phone": 0,
  "students": {"67010001": "attentive", "67010007": "sleeping"},
  "ignored_labels": []
}
fieldความหมาย
statusok · waiting (ยังไม่ได้ส่งครั้งแรก) · error (ดู error)
peopleจำนวนคนในเฟรมที่ส่งล่าสุด
attentive_pct% ตั้งใจของเฟรมนั้น null ถ้าไม่มีกรอบพฤติกรรม
sleeping / inattentive / phoneจำนวนกรอบแต่ละพฤติกรรม (phone เป็น 0 เมื่อปิดฟีเจอร์)
studentsรหัสนักศึกษาที่จำหน้าได้ในเฟรมนี้ → พฤติกรรมที่ผูกได้ (null = จำได้แต่ไม่อยู่ในกรอบใด)
ignored_labelsคลาสที่ยังไม่ได้จับคู่ ไปเพิ่มในหน้าตั้งค่า

ตัวอย่างใช้ใน JavaScript node ถัดไป (ใช้ payload และ print ตามเอกสาร JavaScript Update 2025):

if (payload.spu && payload.spu.status == "ok" && payload.spu.sleeping >= 3) {
  print("มีคนหลับ " + payload.spu.sleeping + " คน");
}

ตัวเลขในตัวอย่างเป็นข้อมูลสมมติ ค่าในหนึ่งเฟรมแกว่งได้ ถ้าจะทำแจ้งเตือนจริงใช้ค่าเฉลี่ยจากข้อ 6.2

6.2 สรุปทั้งห้องแบบนิ่ง: GET /api/live

from cira_bridge import get
live = get("/api/live?session=%d" % SESSION_ID, TOKEN_FILE, timeout=2)   # SESSION_ID จากคำตอบของ /api/cira/frame
k = live["kpi"]
alert = (k["sleeping"] or 0) >= 3                 # None เมื่อยังไม่มีข้อมูล
present = [r["id"] for r in live["roster"] if r["present"]]
fieldความหมาย
sessionคาบ (id, title, room_code, teacher_name, started_at, simulated) หรือ null
cira.statuslive (มีเฟรมใน 5 วิ) · error (ถูกปฏิเสธล่าสุด ดู last_error) · connected · offline
kpi.registered / presentจำนวนที่ลงทะเบียน / เช็คชื่อแล้วในคาบนี้
kpi.attentive_pct% ตั้งใจ รวมทุกเฟรมใน 10 วินาทีล่าสุด
kpi.sleeping / inattentive / peopleค่าเฉลี่ยต่อเฟรมใน 10 วินาที (phone เป็น null เมื่อปิด)
roster[]เฉพาะนักศึกษาในเซ็ค: id, name, present, has_face, status, status_seconds, frames, shares
roster[].statusattentive · inattentive · sleeping · phone · unknown (ยังไม่ยืนยัน) · not_seen (ไม่เห็นเกิน 20 วิ)

6.3 Endpoint อื่นสำหรับ OUTPUT

GET /api/statusคาบที่เปิด + สถานะการเชื่อมต่อ CiRA (เบา ใช้ตรวจว่าต่อติดไหม)
GET /api/sessionsรายการคาบทั้งหมด พร้อมจำนวนเฟรมและจำนวนคนที่มา
GET /api/sessions/<id>/reportสรุปคาบ ไทม์ไลน์รายนาที สัดส่วนพฤติกรรมรายคน
GET /api/sessions/<id>/exportไฟล์ CSV (UTF-8 เปิดใน Excel ได้)

ทุก endpoint ต้องมี header X-API-Key และเรียกได้จากเครื่องเดียวกันเท่านั้น

7. ข้อผิดพลาดที่พบบ่อย

เว็บตอบ HTTP 400 พร้อม {"error": "..."} ภาษาไทย ข้อความเดียวกันจะอยู่ใน payload.spu.error และแถบบนของหน้าเว็บจะขึ้นจุดแดง

ข้อความแปลว่า / วิธีแก้
Connection refused / timed outเว็บไม่ได้รันอยู่ หรือ port ไม่ตรง รัน python app.py แล้วตรวจ BASE_URL
HTTP 401: API key requiredคีย์ไม่ตรง ตรวจ REPO ว่าชี้ไปที่ repo ที่รันเว็บอยู่ (ถ้าลบโฟลเดอร์ data คีย์จะเปลี่ยน)
HTTP 403: Localhost onlyเรียกผ่าน IP เครื่อง ใช้ 127.0.0.1 หรือ localhost เท่านั้น
ยังไม่มีคาบเรียนที่เปิดอยู่ เปิดคาบในหน้าเว็บก่อนเปิดคาบในหน้าห้องเรียน
คาบเรียนไม่ตรงกับคาบที่กำลังเปิดอยู่ส่ง session_id เก่า เอาออก
มีหลายห้องเปิดคาบอยู่ ต้องส่ง room (รหัสห้อง) มาด้วยตั้ง ROOM ใน Python+ ให้ตรงกับห้องของกล้อง
ห้อง 11-501 ยังไม่มีคาบที่เปิดอยู่อาจารย์ยังไม่เริ่มคาบในห้องนั้น หรือรหัสห้องสะกดไม่ตรงกับหน้า "ห้องและเซ็ค"
ไม่พบผลตรวจจับ ต้องมี detections หรือ payload ที่มี <ชื่อ node>.objects ...payload ไม่มี objects หรือมี detector หลายตัว ระบุ function
ต้องส่ง width และ height (พิกเซล) ของภาพที่ใช้ตรวจจับpayload ไม่มี im_w/im_h แนบภาพ หรือส่ง width/height
confidence ต้องอยู่ระหว่าง 0–1 ตรวจการตั้งค่า confidence scaleCiRA ส่ง 0–100 ไปตั้ง "สเกล confidence" เป็น 0–100
confidence, x, y, w, h ต้องเป็นตัวเลขบางรุ่นส่งเป็นข้อความ แปลงเป็น float ก่อนส่ง
w และ h ต้องมากกว่า 0กรอบขนาดศูนย์ กรองทิ้งก่อนส่ง
คาบนี้เป็นคาบจำลอง รับเฉพาะข้อมูลจำลองตัวจำลองเปิดคาบค้างไว้ ปิดคาบนั้นแล้วเปิดคาบจริง
ภาพไม่ถูกต้องหรือใหญ่เกิน 3 MBภาพใหญ่หรือ encode ผิด ใช้ frame_bgr= ของ bridge ซึ่งย่อและ encode ให้
Expected payload.DeepDetect.objects ... (จาก bridge)payload ไม่ใช่รูปแบบที่คาด print(payload) ดูโครงสร้างจริง

อาการที่ไม่มี error แต่ผลไม่ถูก

กรอบเลื่อนไปซ้ายบนครึ่งกรอบข้อมูลเป็นแบบมุม เลือก "มุมซ้ายบน"
กรอบเลื่อนไปขวาล่างครึ่งกรอบข้อมูลเป็นจุดกึ่งกลาง เลือก "จุดกึ่งกลาง"
กรอบเล็กกระจุกมุมซ้ายบนCiRA ส่งสัดส่วน 0–1 แต่ตั้งเป็นพิกเซล
กรอบใหญ่ล้นภาพwidth/height ที่ใช้ไม่ใช่ขนาดของภาพที่ตรวจ (เช่น ใช้ ROI)
ตัวเลขเป็น — ตลอดทุกคลาสยังไม่ได้จับคู่ ดูปุ่ม "+ คลาส" ในหน้าตั้งค่า
เข้าเรียน 0 แม้เห็นหน้าไม่ได้แนบภาพ หน้าเล็ก/ไกลเกินไป ยังไม่มีภาพใบหน้า หรือคนนั้นไม่อยู่ในรายชื่อเซ็ค
flow ช้าลงทุก 1 วินาทีรอเว็บตอบ ลด TIMEOUT หรือตั้ง SEND_IMAGE = False ชั่วคราวเพื่อดูว่าภาพเป็นสาเหตุไหม

8. ขั้นตอนทดสอบและตรวจรับ

ทดสอบจาก terminal ก่อนต่อ flow

# 1) ต่อถึงเว็บไหม (ดูผลในหน้าตั้งค่า "ผลลัพธ์ล่าสุดจาก CiRA")
python integrations/cira_bridge.py --ping

# 2) ส่ง payload ที่คัดลอกจาก Debug มาเป็นไฟล์ (อย่า commit ไฟล์จากห้องจริง)
python integrations/cira_bridge.py payload.json

# 3) ส่งพร้อมภาพเฟรมเดียวกัน
python integrations/cira_bridge.py payload.json --image frame.jpg

เกณฑ์ตรวจรับบน CiRA จริง

  • Debug หลัง Python+ เห็น payload.spu.status = "ok"
  • img ใน Python+ เป็นภาพ BGR (ดูจาก img.shape)
  • ชื่อคลาสจับคู่ครบ ไม่มีปุ่ม "+ คลาส" ค้างในหน้าตั้งค่า
  • กรอบบนหน้าห้องเรียนทับคนในภาพพอดี
  • ภาพ 0 / 1 / หลายคน: จำนวนคนตรงกับที่ตานับ
  • นักศึกษาที่ลงทะเบียนหน้าตรง: ถูกเช็คชื่อ และมีพฤติกรรมในรายชื่อ
  • คนที่ไม่ลงทะเบียน: ไม่ถูกเช็คชื่อเป็นคนอื่น
  • ฟุบหลับ: ยอดหลับของห้องเพิ่ม (ไม่มีชื่อถือว่าถูกตามออกแบบ)
  • ก้มเขียนหนังสือ / หันคุย: จดว่าโมเดลแยกจากหลับได้หรือไม่
  • ปิดเว็บระหว่าง flow รัน: flow ต้องเดินต่อ และ payload.spu.status = "error"
  • ส่งก่อนเปิดคาบหรือหลังปิดคาบ: ถูกปฏิเสธ และแถบบนแสดงเหตุผล
  • เปิดคาบ 2 ห้องพร้อมกัน ส่ง room ต่างกัน: ข้อมูลไปถูกห้อง
  • (ถ้าเปิด) ใช้โทรศัพท์จากมุมกล้องจริง: มองเห็นกี่ครั้งจากกี่ครั้ง เพื่อตัดสินใจว่าจะเก็บฟีเจอร์ไหม

บันทึกผลจริงลงรายงานโครงงาน ห้ามอ้างว่าเชื่อมสำเร็จจากการทดสอบ API หรือข้อมูลจำลองอย่างเดียว

9. ข้อห้ามด้านความปลอดภัยและข้อมูลส่วนตัว

  1. ห้ามพิมพ์ API key ลงใน flow หรือโค้ด ให้อ่านจากไฟล์ทุกครั้ง flow ที่อัปโหลดขึ้น GitHub ต้องไม่มีคีย์
  2. ห้ามเปิดเว็บให้เครื่องอื่นเข้าถึง (ห้ามเปลี่ยน host เป็น 0.0.0.0) เพราะยังไม่มีระบบล็อกอินและ HTTPS
  3. ห้าม commit โฟลเดอร์ data/, ภาพ, payload หรือ CSV จากห้องเรียนจริง repo นี้เป็น public
  4. ลงทะเบียนเฉพาะคนที่ยินยอม และลบข้อมูลได้เมื่อขอ (หน้า "นักศึกษา" ปุ่มลบ)
  5. ผลพฤติกรรมเป็นการประเมินของโมเดล ห้ามใช้ตัดคะแนนหรือลงโทษ แจ้งนักศึกษาก่อนทดลอง

ทิศendpointใช้ทำอะไร

INPOST /api/recognizeทางเดิม: เช็คชื่อจากภาพอย่างเดียว

OUTGET /api/live?session=<id>KPI 10 วินาที, รายชื่อในเซ็คพร้อมสถานะ, เฟรมล่าสุด
OUTGET /api/live/frameภาพ JPEG เฟรมล่าสุด (404 ถ้าไม่มี)
OUTGET /api/statusคาบที่เปิด + สถานะ CiRA
OUTGET /api/sessions/<id>/report · /exportสรุปคาบ ไทม์ไลน์ รายคน · CSV
OUTGET /api/cira/outputsผลล่าสุดของแต่ละ function
